Rules for new components

  1. Check shadcn/ui first. If a primitive exists there, adopt its API and restyle it — never invent a parallel one.
  2. Extend, don't substitute. ink, success, warning are additions to shadcn's variants.
  3. Radix underneath anything with interaction semantics — menus, dialogs, tabs, selects.
  4. Tokens, never literals. A hex in a component is a bug.
  5. Ship the pair. Done means the specimen and the TSX agree, with Vitest coverage.
