Component conventions

One name per concept. When two components spell the same idea differently, every consumer has to learn both — so the canon below is enforced across the system. Where a prop was renamed, the old name still works as a deprecated alias; nothing in flight breaks.

Focus

  • Every element you can click or key into carries :focus-visible with var(--ring) — a 3px Just Blue glow, never a hard outline. Table rows, which cannot paint a shadow under border-collapse, use a tinted row with a hairline instead.
  • Focus-visible, not focus — a mouse click should not leave a ring behind. Text fields are the exception: Input and Select ring on plain :focus, because an active field must look active however you got there.
  • Touch targets still need it: an operator with a keyboard-equipped tablet gets the same affordance.

Every collection has three states

  • Loading — skeletons in the shape of the content, never a spinner over a blank panel.
  • Empty — say what is missing and how it arrives, not just "no data".
  • Populated.
  • Grids, feeds, widgets and tables all implement the set. A component that can be empty and isn't handling it is unfinished.

Structural rules

RuleWhy
Stacked labels are blockA title and subtitle rendered as sibling <span>s inherit display:inline and run together on one line — margins silently do nothing. Set display:block, or use flex column.
Width floors go on the rootA min-width on an inner list lets the flex root shrink while the content spills over its neighbour. Constrain the element the parent is sizing.
Scroll containers need min-height:0A flex child defaults to min-height:auto, so a tall body grows past the container and pushes the footer out of view instead of scrolling.
Tokens, never literalsA hex in a component is a bug. If a value is missing from the token set, add the token.
Shell owns the frameCharts, lists, stats and tables never draw their own card — Widget does, so panels stay interchangeable.
